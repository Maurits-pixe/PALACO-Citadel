## Human behavior and boundary

The exercise's fixed insufficient-evidence explanation and answer status use the
chosen VisitCard language. They also follow subsequent explicit language choices.
There are seven supported languages, including Arabic RTL. An existing supported
answer continues to quote the visitor's memory exactly; it is not translated.

This is a web-adapter presentation change. The core Engine result, saved question,
memory content, citations, dossier identifiers and provenance remain unchanged.
The Dutch canonical abstention in the recorded core result is not rewritten.
The adapter maps its known insufficient-evidence state to equivalent local copy.

The existing `data-engine-i18n` path labels the visible status and fixed
explanation. Private remembered text has no translation key; `lang=""` declares
its unknown language and `dir="auto"` lets its actual text determine direction.
No source language is inferred from the selected interface. Fixed explanation
text has the actual chosen language and corresponding LTR/RTL direction.

Clearing or replacing the exercise removes dynamic translation keys and answer
language/direction metadata along with its current visible answer. A later
language choice therefore cannot recreate hidden old status, explanation or
private content. No private answer cache, query replay or new persistence is added.
Existing input drafts, chat, selected subject and consent boundaries are preserved.

Only `rio-engine-web.mjs` and root cache version v47 change in the public bundle.
The other twenty public files, including core `engine.mjs`, chat, styles,
integration, app/NOVA and offline download, stay byte-identical to the baseline
package. App cache remains v7; root waiting activation is unchanged.
